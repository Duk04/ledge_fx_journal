# Ledger — project invariants

The block above is regenerated by `next dev`. Keep everything below the END
marker and never edit inside the markers.

`README.md` says what the app is. `docs/` is the reference layer and is
cross-referenced from code comments — if you change behaviour a doc describes,
update the doc in the same commit.

## Layers, one direction only

    page / layout   ->  src/lib/queries/*  ->  src/lib/db.ts
    server action   ->  src/lib/actions/*  ->  src/lib/db.ts

- Only `src/lib/queries/*`, `src/lib/actions/*`, `src/lib/session.ts`,
  `src/lib/auth*.ts`, `src/lib/active-account.ts` and `src/app/api/**` may
  import `{ prisma }` from `@/lib/db`. Pages and components must not — add a
  function to `src/lib/queries/` and pass the result down as props.
- `src/app/api/**` route handlers are a deliberate exception: they are peers
  of pages, not a layer above them, and they stream bytes rather than render.
- Every server-side module starts with `import "server-only"`.

## The scoping rule (non-negotiable)

No query is written without a `userId` — or an account row already confirmed
to belong to the current user — in its WHERE clause.
`requireAccountAccess()` is where that confirmation happens; build queries off
the row it returns, never off an `accountId` taken from a URL or form field.
It throws `NotFoundError` rather than a permission error on purpose, so
account ids cannot be enumerated.

**Two deliberate exceptions:** `Instrument` and `Candle` are shared reference
data with no `userId` (`src/lib/queries/candles.ts` explains why duplicating
bars per user is the wrong trade). For those the rule is: reads unscoped,
every WRITE gated by `requireOwner()`.

## Server actions

**Every export of a `"use server"` module is a callable POST endpoint** —
including a helper exported only because it felt tidy, and including one
nothing imports. So:

- Every exported action authenticates. There is no "the page already checked":
  a Server Function is a POST to its own route and does not pass through the
  middleware matcher.
- A helper that should not be an endpoint goes in a different file with
  `import "server-only"`. There is no "internal export" escape hatch.
- `src/lib/actions/server-action-surface.test.ts` asserts both, from source
  text. If it fails, do not weaken it.

**Actions never throw.** A Server Action wired to a form's `action` prop has
no caller-side try/catch, so a rejected promise breaks the page instead of
showing an error. Return `{ ok: false, formError }` / `{ ok: false,
fieldErrors }`. Catch `NotFoundError` and `ForbiddenError` from
`@/lib/errors` and convert them.

## Untrusted input that is code

Strategy source (`Strategy.code`) is compiled and executed **only in a Web
Worker in the author's own browser** (`src/lib/backtest/worker.ts`). Never in
a server module. `src/lib/backtest/index.ts` does not re-export `./sandbox`
for this reason, and a test asserts no action reaches `compileStrategy`.

The sandbox's allowlist is defence against typos, not against attackers:
`"".constructor.constructor` reaches `Function` from a bare string literal,
naming nothing any shadow list could cover. `sandbox.test.ts` asserts the
escapes *work*. Do not add shadows believing they close the hole, and read
`docs/BACKTEST-ENGINE.md` before touching any of it.

Server-side validation of that source parses without executing —
`checkStrategySyntax()` in `strategy-source.ts`. `new Function(body)` compiles
and returns; nothing invokes the result.

## Numbers

- `src/lib/metrics/*` computes in `decimal.js`. Money and R multiples never
  touch a float there. Prisma `Decimal` <-> `decimal.js` conversion goes
  through `src/lib/decimal-bridge.ts` and nothing else.
- `src/lib/backtest/*` runs on plain `number` on purpose: it is a hot loop
  over hundreds of thousands of bars. The two worlds meet at
  `toJournalTrade()`, which is the only bridge.
- Quote-currency conversion is resolved explicitly in `src/lib/conversion.ts`
  and never allowed to default silently — a JPY-quoted trade in a USD account
  is wrong by two orders of magnitude if it does.
- Indicators in `src/lib/backtest/indicators.ts` return arrays the **same
  length** as their input, `null` through the warm-up. Read that file's header
  before touching them: a shortened array is a look-ahead bug, and it shows up
  as suspiciously good backtest results rather than a crash.
- `src/lib/metrics/aggregate.ts:40-60` documents the judgement calls
  (breakevens, expectancy, streaks, deposits and high-water marks). Those are
  decisions, not accidents. Don't "simplify" them without reading it.

## UI

- `src/components/ui/` is a hand-rolled Radix + design-token kit. It is **not**
  shadcn: there is no `components.json`, no `cva`, and `npx shadcn add` will
  not work. Import from the `@/components/ui` barrel, not individual files.
- Tokens live in `src/app/globals.css`. Never a raw hex, an arbitrary Tailwind
  value, or a stock palette colour in component code. `docs/DESIGN-SYSTEM.md`
  lists the tokens; `docs/COMPONENTS.md` says when to reach for each primitive
  and when not to; `/design` renders every primitive in every state from the
  real source — look there before building a new one.
- Error boundaries take a `retry` prop (stable since Next 16.3), not `reset`.
  Model new ones on `src/app/(app)/error.tsx`.
- A control the current user may not use is hidden or disabled, with a reason
  in the `title` — not left to fail on submit.

## Comments

This codebase explains *why*, not *what*. `src/lib/backtest/sandbox.ts`,
`src/lib/backtest/indicators.ts` and `src/lib/metrics/aggregate.ts` are the
standard; match it. Do not strip a comment because the code "looks obvious".

**A comment that has become false is a bug.** Fix it in the same commit as the
behaviour change, and if you find one that was already false, say so rather
than quietly deleting it — several of the worst problems in this repo's
history were visible only as a comment that no longer matched the code.

## Before you say you're done

    npm run verify     # typecheck + lint (--max-warnings 0) + unit tests

`npm ci` runs `prisma generate` via `postinstall`. If tsc reports missing
Prisma models, the client is stale — regenerate before debugging anything
else. `npm run build` is the only check that catches a client/server boundary
mistake.
